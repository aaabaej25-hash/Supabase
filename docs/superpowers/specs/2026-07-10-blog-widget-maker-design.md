# 네이버 블로그 위젯 메이커 — 디자인 스펙

- 작성일: 2026-07-10
- 상태: 사용자 리뷰 대기
- 관련 문서: 없음 (기존 apt_landing/book_toc와는 독립된 별도 프로젝트, 스택 공유 없음)
- 참고: https://imhama.com/blog_maker_imhama ("내가하마 상담소 — 홈페이지형 블로그 반자동 생성기") — 로그인 필요라 실제 UI는 사용자가 제공한 스크린샷 2장으로 파악

## 1. 개요

네이버 블로그를 "홈페이지처럼" 꾸밀 수 있게, 블로그 정보(이름·슬로건·운영시간·이미지·메뉴 등)를 입력받아 **네이버 블로그 위젯 등록용 HTML 코드**와 **스킨 배경 이미지 파일(PC/모바일 규격)**을 생성해주는 **브라우저 전용 정적 웹앱**.

이 도구는 네이버 블로그를 대신 만들거나 호스팅하지 않는다 — 사용자가 직접 네이버 블로그 관리자 화면에 코드를 붙여넣고 이미지를 업로드하는 마지막 단계는 항상 수동이다. 도구의 책임은 "그 코드와 이미지를 정확하고 빠르게 만들어주는 것"까지다.

### 확정된 요구사항

| 항목 | 결정 |
|------|------|
| 결과물 형태 | 네이버 블로그 위젯 HTML 코드(복사용) + 배경 이미지 파일(다운로드용). 사이트를 직접 호스팅하지 않음 |
| 사용 주체 | 누구나 쓰는 무료 도구 (로그인 없음, SaaS 아님) |
| 데이터 저장 | 없음 — 모든 입력은 세션(브라우저 메모리) 내에서만 유지, 새로고침하면 초기화 |
| AI 사용 | 없음 — 순수 폼 입력 → 코드/이미지 변환만 수행 |
| 위젯 내 이미지 소스 | 서버가 호스팅하지 않음. 사용자가 이미지를 외부에 직접 업로드(예: 네이버 블로그 게시물 첨부)하고, 그 URL을 폼에 직접 입력 |
| 배경 이미지(PC 1920×700, 모바일 700×700) | 사용자가 업로드한 사진을 브라우저에서 규격에 맞게 크롭/리사이즈해 다운로드 파일로 제공. URL 불필요(네이버 스킨 설정에 파일로 직접 업로드하는 방식) |
| 비용 | 무료 — 외부 API 호출 없음, 서버 없음, 정적 파일만 실행 |

### 선택한 접근 (안 A)

빌드 도구·서버 없는 순수 정적 웹앱(HTML + CSS + 바닐라 JS). 이미지 크롭/리사이즈는 브라우저 `<canvas>` API로 처리.

- 확정 요구사항(저장 없음·AI 없음·서버 이미지 저장 없음)을 만족시키는 데 서버가 할 일이 실질적으로 없음
- 정적 파일이라 배포가 곧 "폴더 하나 올리기" — GitHub Pages 등 무료 호스팅으로 충분
- 검토 후 기각한 대안:
  - **FastAPI + Jinja2 + Pillow** (리포의 다른 프로젝트와 스택 일치): 서버가 할 일이 없는데 컨벤션 일치만을 이유로 서버를 두는 것은 불필요한 복잡도
  - **하이브리드**(정적 프론트 + 이미지 크롭만 서버 Pillow): 브라우저 canvas로 고정 비율 크롭은 충분히 안정적이라 서버를 별도로 둘 이유가 약함

## 2. 아키텍처

```
[브라우저에서 여는 정적 페이지 (index.html)]
  │
  ├─ ① 정보 입력 폼: 블로그명/슬로건/운영시간/프로필이미지 URL/배경색/대표링크 4종/메뉴 최대 5개
  ├─ ② 배경 이미지 크롭 도구: 사진 업로드 → PC(1920×700)/모바일(700×700) 크롭 → PNG 다운로드
  ├─ ③ 위젯 코드 생성기: 폼 상태 변경 시 실시간으로 위젯 HTML 코드 2종 재생성 + 복사 버튼
  ├─ ④ 미리보기 패널: 생성된 위젯이 네이버 위젯 폭(~170px) 기준으로 어떻게 보이는지 렌더링
  └─ ⑤ 단계별 체크리스트: 1~8단계 안내(②③④에 해당하는 단계는 도구 내 앵커로 연결, 나머지는 네이버에서 사용자가 직접 수행하는 안내 텍스트)
```

- **프로젝트 위치**: 이 리포에 `blog_widget_maker/` 폴더로 추가 (apt_landing/book_toc와 형제, 스택은 독립적)
- **데이터 저장**: 없음. 모든 상태는 JS 메모리의 단일 state 객체 (`localStorage`/DB 사용 안 함 — 새로고침 시 초기화가 의도된 동작)
- **실행 방법**: `index.html`을 브라우저로 직접 열거나, 로컬 확인용으로 `python -m http.server`를 `.claude/launch.json`에 정적 서버 설정으로 추가
- **외부 의존성**: 없음 (프레임워크·CDN·API 없음, 모든 코드는 폴더 내 순수 JS)

## 3. 컴포넌트

### 3.1 `index.html` — 페이지 구조

폼 섹션 / 크롭 도구 섹션 / 코드 출력 섹션 / 미리보기 섹션 / 체크리스트 섹션을 한 페이지에 배치. `<template>` 태그로 메뉴 항목 반복 UI(최대 5개) 구성.

### 3.2 `app.js` — 상태 관리 & 렌더링 오케스트레이션

- 단일 `state` 객체: `{ blogName, slogan, hours, profileImageUrl, bgColor, quickLinks: {home, blogMap, reserve, phone}, menus: [{icon, text, url}] (최대 5개) }`
- `bgColor`는 프리셋 4종(화이트/블랙/오렌지/네이비) 버튼 선택 + 커스텀 hex 직접 입력을 모두 지원. 프리셋 선택 시 해당 hex 값이 `bgColor`에 그대로 들어가는 방식으로 통일(내부적으로 "프리셋이냐 커스텀이냐"를 구분하는 별도 플래그는 두지 않음)
- 모든 입력 요소에 `input`/`change` 리스너 → `state` 갱신 → `renderWidgetCode(state)` + `renderPreview(state)` 재호출
- 메뉴 항목 추가/삭제 버튼: 5개 도달 시 추가 버튼 `disabled` + 안내 문구 표시
- 체크리스트 항목 체크 상태는 별도의 로컬 state로 관리 (저장 안 함, 세션 내 UI 상태일 뿐)

### 3.3 `widget-templates.js` — 위젯 코드 생성 함수

- `renderProfileWidgetCode(state)`: 프로필 이미지 + 블로그명 + 슬로건 + 운영시간 + 대표링크 4종 아이콘을 담은 위젯 HTML 문자열 반환
- `renderMenuWidgetCode(state)`: 메뉴 항목(아이콘+텍스트+URL) 리스트를 담은 위젯 HTML 문자열 반환
- 두 함수 모두 순수 함수(입력 state → 출력 문자열, DOM 접근 없음)로 작성해 Node 테스트에서 그대로 호출 가능하게 함
- 필수 필드(블로그명)가 비어 있으면 플레이스홀더 텍스트("블로그명을 입력하세요")로 대체 — 에러로 막지 않음

### 3.4 `cropper.js` — 배경 이미지 크롭/리사이즈

- 파일 업로드 → `FileReader`로 이미지 로드 → `<canvas>`에 그려 PC(1920×700)/모바일(700×700) 두 비율 각각 드래그로 크롭 영역 조정 가능한 간단한 크롭 UI
- "다운로드" 버튼: `canvas.toBlob()` → PNG 파일 다운로드 (파일명: `bg-pc-1920x700.png`, `bg-mobile-700x700.png`)
- 크롭 좌표 계산(비율 유지, 캔버스 좌표 ↔ 원본 이미지 좌표 변환) 로직은 별도 순수 함수로 분리해 테스트 가능하게 함

### 3.5 `icons/` — 메뉴 아이콘 세트

스크린샷 기준 자주 쓰이는 아이콘(홈/공간안내/이용요금/오시는길/전화걸기 등) SVG 세트를 내장. 메뉴 항목의 아이콘 선택은 이 세트 중 드롭다운으로 선택.

### 3.6 미리보기 패널

생성된 위젯 코드를 `iframe.srcdoc` 또는 격리된 `<div>`에 렌더링해 실제 네이버 위젯 폭(~170px) 근사치로 좌측에 보여줌. 코드와 미리보기는 항상 동일한 렌더 함수의 출력을 공유해 "보이는 대로 나온다"를 보장.

## 4. 데이터 흐름

1. 사용자가 폼 필드 입력 → `state` 갱신
2. `state` 변경 → `renderWidgetCode(state)` 호출 → 코드 블록 텍스트 갱신 + 미리보기 갱신 (같은 프레임 내 동기 처리, 별도 API 호출 없음)
3. 이미지 크롭 도구는 `state`와 무관한 독립 플로우 — 업로드한 이미지는 위젯 코드에 들어가지 않고 파일로만 다운로드됨
4. "복사" 버튼 클릭 → `navigator.clipboard.writeText()`로 코드 블록 텍스트 복사, 성공 시 버튼에 짧게 "복사됨" 피드백

## 5. 에러 처리

- URL 필드(프로필 이미지 URL, 메뉴 링크 URL 등): 형식이 `http(s)://`로 시작하지 않으면 인라인 경고만 표시하고 값 자체는 그대로 반영 (네이버 특수 링크 형식 존재 가능성 고려, 강제 차단 안 함)
- 이미지 업로드: JPG/PNG/WEBP 외 형식이나 10MB 초과 파일은 업로드 거부 + 안내 메시지
- 메뉴 5개 초과 시도: 추가 버튼 비활성화, "최대 5개까지 등록 가능합니다" 문구
- 필수 필드(블로그명) 미입력: 코드 생성은 계속 동작하되 플레이스홀더로 표시해 진행을 막지 않음
- `navigator.clipboard` 미지원 브라우저: 복사 실패 시 코드 블록을 자동 선택 상태로 만들어 수동 복사(Ctrl+C) 유도

## 6. 테스트

- 빌드 도구가 없으므로 순수 함수(`renderProfileWidgetCode`, `renderMenuWidgetCode`, 크롭 좌표 계산 함수)를 대상으로 `node --test` 기반 경량 단위 테스트 작성 (리포의 기존 pytest 인프라와는 무관한 별도 스택)
- 브라우저 동작(이미지 업로드/크롭/다운로드, 복사 버튼, 실시간 미리보기 반영)은 preview 도구로 수동 검증: 폼 입력 → 코드 실시간 갱신 확인 → 복사 버튼 동작 확인 → 이미지 업로드 후 두 비율 크롭·다운로드 확인

## 7. 알려진 한계 / 스코프 밖

- 네이버 블로그 실제 위젯 등록·스킨 배경 업로드·카테고리 생성·블로그 개설·스킨 선택은 모두 사용자가 네이버 관리자 화면에서 직접 수행해야 하는 수동 단계이며, 이 도구는 자동화하지 않는다 (체크리스트로 안내만 함)
- 위젯 코드는 네이버 블로그의 위젯 HTML 허용 범위(스크립트 제한, 폭 제약 등)를 준수하는 일반적인 정적 HTML/CSS로 생성하지만, 네이버 정책이 바뀌어 특정 태그/속성이 막힐 경우 실제 등록 시 깨질 수 있다 — 이는 사용자가 네이버에 붙여넣을 때 확인해야 하는 부분
- 이미지 호스팅(위젯용 프로필/아이콘 이미지)은 사용자 책임이며, 사용자가 입력한 URL이 만료되거나 삭제되면 위젯이 깨진다 — 도구가 URL 유효성을 지속적으로 검증하지 않는다
