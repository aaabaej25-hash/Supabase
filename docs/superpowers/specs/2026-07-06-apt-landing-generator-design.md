# 아파트 랜딩페이지 자동 생성기 — 디자인 스펙

- 작성일: 2026-07-06
- 상태: 사용자 리뷰 대기
- 관련 문서: 없음 (PipeCraft 디자인 요청서와는 별개의 독립 프로젝트)

## 1. 개요

아파트 매물/분양 정보와 사진을 입력하면 랜딩페이지를 자동 생성하고, GitHub Pages에 배포해 공유용 URL을 발급하는 **개인용 로컬 웹앱**. 고객 문의는 랜딩페이지의 카카오톡 채널/오픈채팅 링크 버튼으로 받는다(서버 연동 없음).

### 확정된 요구사항

| 항목 | 결정 |
|------|------|
| 사용 주체 | 본인이 직접 쓰는 내부용 도구 (SaaS 아님) |
| 도구 형태 | 로컬 웹앱 (FastAPI, localhost) |
| 카톡 문의 수신 | 카카오톡 채널 1:1 채팅 또는 오픈채팅방 **링크 버튼** — 서버·사업자 등록 불필요 |
| 카피 생성 | Ollama(로컬 LLM)가 자동 생성, 사용자가 수정 후 확정 |
| 디자인 방식 | 참고 URL에서 **스타일만 추출**(색상·섹션 구성·카피 톤) → 베이스 템플릿 1종에 적용. 참고 URL 없으면 기본 스타일 |
| 배포 | 정적 사이트 빌드 → GitHub Pages 자동 배포 → URL 발급 (무료) |

### 선택한 접근 (안 A)

Python(FastAPI) 로컬 웹앱 + Jinja2 정적 빌드 + GitHub Pages 배포.

- 기존 스택(Python·Ollama·config.toml 패턴)과 일치, 서버 비용 0원
- 미리보기와 배포 결과물이 동일한 HTML — 보이는 대로 배포됨
- 대안으로 검토 후 기각: Streamlit(미리보기/편집 UX 한계), Next.js 풀스택(새 스택 도입 과함)

## 2. 아키텍처

```
[관리 웹앱 (localhost:8000, FastAPI)]
  │
  ├─ ① 매물 입력: 아파트 정보 폼 + 사진 업로드 + 참고 URL + 카톡 링크
  ├─ ② 스타일 추출: 참고 URL → HTML/CSS 파싱 → 스타일 가이드(JSON)
  ├─ ③ 카피 생성: 매물 정보 + 카피 톤 → Ollama → 헤드라인/섹션별 문구
  ├─ ④ 편집·미리보기: 카피 수정, 사진 순서 조정 → 실제 HTML iframe 미리보기
  └─ ⑤ 배포: Jinja2 렌더 → 정적 사이트 → gh CLI로 GitHub Pages 푸시 → URL 발급
```

- **프로젝트 위치**: 이 리포에 `apt_landing/` 패키지로 추가 (youtube_summarizer와 형제). 추후 분리 시 폴더째 이동 가능
- **데이터 저장**: DB 없음. 매물 하나 = 리포 루트 `projects/<매물슬러그>/` 폴더 (`project.json` + `photos/` + `build/`). `projects/`는 `.gitignore`에 추가 (매물 데이터는 개인 데이터이므로 리포에 커밋하지 않음)
- **설정**: 기존 `config.toml`에 `[apt_landing]` 섹션 추가 — Ollama 모델·엔드포인트, 배포 리포 경로/이름, GitHub Pages 기본 URL
- **랜딩페이지 산출물**: 순수 HTML/CSS(+최소 JS) 정적 사이트
- **배포 대상**: 별도 GitHub 리포(예: `apt-pages`)에 매물별 하위 폴더 → `https://<계정>.github.io/apt-pages/<매물슬러그>/`

## 3. 컴포넌트

### 3.1 `models.py` — 데이터 모델

- `Project`: 매물 정보(단지명, 위치, 평형/가격 리스트, 입주시기, 특장점 메모), 카톡 링크, 참고 URL, 사진 목록(순서 포함), 상태(초안 → 카피확정 → 배포됨), 배포 URL
- `StyleGuide`: 색상 팔레트(주조·보조·배경), 중간 섹션 순서, 카피 톤 설명(한 문장). 기본값 내장 — 추출 실패 시 폴백. "섹션 순서"는 베이스 템플릿의 중간 3개 섹션(핵심정보·입지·갤러리)의 배열 순서만 의미한다 — 히어로는 항상 처음, 문의 CTA는 항상 마지막으로 고정
- `Copy`: 섹션별 문구 — 히어로 헤드라인/서브, 핵심정보 요약, 입지 문단, 갤러리 캡션, CTA 문구
- 전체를 `project.json` 하나에 직렬화 (사진 파일 제외)

### 3.2 `style_extractor.py` — 참고 URL 분석

- `httpx`로 HTML 수신 → CSS 색상 값 빈도 분석으로 팔레트 추출, 헤딩/섹션 태그로 구성 순서 추정
- 본문 텍스트를 Ollama에 전달해 카피 톤을 한 문장으로 요약
- **한계 명시**: 정적 HTML만 파싱. JS 렌더링 페이지 등으로 추출 결과가 빈약하면 기본 스타일 가이드로 폴백하고 UI에 "추출 실패, 기본 스타일 사용"을 표시한다 (조용한 폴백 금지)

### 3.3 `copywriter.py` — Ollama 카피 생성

- 기존 youtube_summarizer의 Ollama 호출 패턴 재사용 (`config.toml`에서 모델·엔드포인트 설정)
- 입력: 매물 정보 + 스타일 가이드의 카피 톤 / 출력: 섹션별 카피 JSON
- 섹션 단위 개별 재생성 지원 (전체 재생성 불필요)

### 3.4 `builder.py` — 정적 사이트 빌드

- Jinja2 베이스 템플릿 1종: 히어로 → 핵심정보 → 입지 → 갤러리 → 문의 CTA
- 스타일 가이드를 CSS 변수로 주입 (색상·섹션 순서)
- 사진: Pillow로 리사이즈·WebP 변환, 원본 보존
- 출력: `projects/<슬러그>/build/` — 미리보기와 배포가 같은 산출물 사용

### 3.5 `deployer.py` — GitHub Pages 배포

- `apt-pages` 리포 로컬 클론에 `build/`를 매물 폴더로 복사 → commit → push
- 재배포 = 폴더 덮어쓰기, 게시 중단 = 폴더 삭제 후 push
- 성공 시 배포 URL을 `project.json`에 기록

### 3.6 `app.py` + `templates/admin/` — FastAPI 관리 UI

화면 4개, 서버 렌더링 HTML + 최소 JS:

1. **매물 목록**: 상태·배포 URL 표시, 새 매물 생성
2. **매물 편집**: 정보 폼, 사진 업로드/순서, 참고 URL, 카톡 링크
3. **카피 편집 + 미리보기**: 섹션별 카피 텍스트 편집·재생성 버튼, 실제 빌드 HTML iframe 미리보기
4. **배포 결과**: 배포 실행, URL 복사

## 4. 데이터 흐름

```
입력 저장 → (참고 URL 있으면) 스타일 추출 → 카피 생성
  → 사용자 수정·확정 → 빌드 → 미리보기 확인 → 배포 → URL 발급
```

각 단계 산출물이 `project.json`에 누적 저장되어, 언제든 특정 단계만 다시 실행할 수 있다 (예: 카피만 재생성, 사진만 교체 후 재빌드).

## 5. 에러 처리

원칙: **죽지 않고, 무엇이 잘못됐는지 화면에 보여주고, 재시도 가능하게.**

| 상황 | 처리 |
|------|------|
| Ollama 연결 실패/타임아웃 | 에러 메시지 표시("Ollama 실행 확인"), 데이터 유지. 섹션별 생성이라 일부 실패해도 성공분 보존 |
| 스타일 추출 실패 (접근 불가, JS 렌더링, 색상 빈약) | 기본 스타일로 자동 폴백 + UI에 폴백 사실 명시 |
| 카피 JSON 형식 오류 (LLM이 형식 위반) | 1회 자동 재시도 → 실패 시 원문 표시 후 수동 편집 유도 |
| 배포 실패 (git push, 네트워크) | git/gh stderr를 화면에 표시. 로컬 build/ 보존, 재시도로 복구 |
| 사진 처리 실패 (손상, 미지원 포맷) | 해당 파일만 건너뛰고 목록에 실패 표시 |
| 슬러그 충돌 (같은 매물명 재사용) | 덮어쓰기/새 이름 선택 확인 |

## 6. 테스트

기존 `tests/` 구조를 따라 pytest 사용.

- **단위 테스트**
  - `style_extractor`: 고정 HTML 픽스처 → 색상·섹션 추출 검증, 빈약한 입력 시 폴백 검증
  - `copywriter`: Ollama 응답 mock → JSON 파싱·재시도 로직 검증
  - `builder`: 샘플 프로젝트 → 결과 HTML에 매물 정보·카톡 링크·CSS 변수 포함 확인
  - `models`: 직렬화 왕복(round-trip) 검증
- **통합 테스트**: 샘플 project.json + 사진으로 빌드 파이프라인 전체 실행 → build/가 완전한 정적 사이트인지 확인. 배포는 dry-run(git 명령 구성만 검증)
- **수동 E2E**: Ollama 실제 호출 + GitHub Pages 실제 배포를 첫 매물 1건으로 검증

## 7. 범위 제외 (Non-Goals)

- 회원/멀티유저, SaaS화 (추후 검증 후 별도 프로젝트)
- 카카오 알림톡/메시지 API 연동 (사업자 등록 필요 — 현재 방식은 링크 버튼으로 충분)
- 템플릿 다종 지원, AI 레이아웃 생성 (베이스 템플릿 1종으로 시작)
- 방문 통계/CRO (필요 시 배포 페이지에 무료 애널리틱스 스크립트만 삽입 가능하도록 여지)
- 커스텀 도메인 연결 (GitHub Pages 기본 URL 사용)
