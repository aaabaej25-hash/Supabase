# 에세이 첨삭 도우미 — 디자인 스펙

- 작성일: 2026-07-12
- 상태: 사용자 리뷰 대기
- 관련 문서: 없음 (blog_widget_maker와 스택 패턴만 공유, 코드는 독립)

## 1. 개요

사용자가 쓴 에세이 초안을 정해진 스타일 지침에 따라 AI(ChatGPT/Claude 웹)로 첨삭받을 수 있도록, **완성된 첨삭 프롬프트를 생성·복사해주는 브라우저 전용 정적 웹앱**. AI 결과물을 다시 붙여넣으면 원문과 나란히 비교하고, 브라우저(localStorage)에 히스토리로 저장한다.

이 도구는 AI API를 직접 호출하지 않는다 — 첨삭 자체는 사용자가 자기 AI 챗 계정에서 수행한다. 도구의 책임은 "지침이 정확히 반영된 프롬프트를 만들어주고, 결과를 비교·보관하는 것"까지다.

### 확정된 요구사항

| 항목 | 결정 |
|------|------|
| AI 엔진 | 없음(API 호출 안 함) — 프롬프트 생성기 방식. 사용자가 ChatGPT/Claude 웹에 복사-붙여넣기 |
| 스타일 지침 적용 | 체크박스로 글마다 선택 (심리·철학 쉽게 / 후킹 문구 / 따뜻한 위로·희망 / 직장인 공감) |
| 상황 제시(기타) | 자유 입력란 — 입력 시 프롬프트에 상황 지시로 반영 |
| 발행 플랫폼 | 체크박스로 선택 (네이버 블로그 / 브런치 / 인스타그램 / 일반) — 선택에 따라 문체·문단 길이·형식 가이드가 프롬프트에 추가 |
| 결과물 처리 | 첨삭 결과를 앱에 붙여넣어 원문과 좌우 비교(모바일은 상하) |
| 데이터 저장 | localStorage 히스토리 — 날짜·제목(원문 첫 줄)·원문·결과·선택 옵션 저장, 불러오기/삭제 지원 |
| 비용 | 무료 — 외부 API 없음, 서버 없음, 정적 파일만 실행 |

### 선택한 접근

빌드 도구·서버 없는 순수 정적 웹앱(HTML + CSS + 바닐라 JS). blog_widget_maker와 동일한 패턴.

- 검토 후 기각한 대안:
  - **React + Vite**: 폼 + 텍스트 조합 + localStorage 규모에 빌드 도구는 과함
  - **Python Flask**: 모든 로직이 클라이언트 텍스트 조합이라 서버가 할 일이 없음

## 2. 아키텍처

```
[브라우저에서 여는 정적 페이지 (index.html)]
  │
  ├─ ① 글 입력: 초안 텍스트영역(글자 수 표시)
  ├─ ② 옵션 선택: 스타일 지침 체크박스 4종(기본 전체 선택) + 상황 제시 자유 입력 + 플랫폼 체크박스
  ├─ ③ 프롬프트 생성: 버튼 클릭 → 미리보기 표시 → 클립보드 복사
  ├─ ④ 결과 비교: 첨삭 결과 붙여넣기 → 원문·결과 나란히 비교 뷰
  └─ ⑤ 히스토리: localStorage 저장/불러오기/삭제 목록
```

- **프로젝트 위치**: 이 리포에 `essay_helper/` 폴더로 추가 (형제 프로젝트들과 독립)
- **실행 방법**: `index.html`을 브라우저로 직접 열거나 `python -m http.server` (`.claude/launch.json`에 추가)
- **외부 의존성**: 없음 (프레임워크·CDN·API 없음)

## 3. 컴포넌트

### 3.1 `index.html` — 페이지 구조

입력 섹션 / 옵션 섹션 / 프롬프트 출력 섹션 / 비교 섹션 / 히스토리 섹션을 한 페이지에 위→아래 흐름으로 배치.

### 3.2 `prompts.js` — 지시문 데이터 (수정 지점)

프롬프트 텍스트만 모아둔 데이터 모듈. 로직 없음. 지침 문구를 다듬고 싶을 때 이 파일만 고치면 된다.

- `ROLE_PREAMBLE`: 역할 정의("당신은 에세이 첨삭 전문가…") + 공통 안전장치("원문의 경험과 핵심 메시지는 유지하고 표현과 구성만 다듬어라", "결과는 수정된 에세이 전문으로만 출력")
- `STYLE_GUIDES`: 지침 id → 구체 지시문
  - `psychology`: 심리·철학 개념이 나오면 전문용어 대신 일상 언어와 비유로 풀어쓰기
  - `hooking`: 에피소드 도입부에 궁금증을 일으키는 후킹 문구 넣기, 밋밋한 서술을 생동감 있게
  - `warmth`: 따뜻한 위로·용기·희망이 느껴지는 긍정적 톤으로 마무리
  - `worker`: 직장인이 "내 얘기네" 하고 공감할 디테일 살리기
- `PLATFORM_GUIDES`: 플랫폼 id → 형식 지시문
  - `naver`: 짧은 문단(2~3문장), 가독성 중심, 소제목 활용
  - `brunch`: 에세이 톤의 긴 호흡, 문학적 문체
  - `instagram`: 짧은 호흡, 카드뉴스형 문장, 줄바꿈 잦게
  - `general`: 플랫폼 중립적 일반 에세이 스타일

### 3.3 `app.js` — 상태 관리 & 조립 & 히스토리

- `state`: 원문, 선택된 지침 배열, 상황 텍스트, 선택된 플랫폼 배열, 결과문
- `buildPrompt(state)`: **순수 함수.** ROLE_PREAMBLE + 선택 지침들 + 상황 지시 + 플랫폼 가이드 + 원문을 조립해 문자열 반환. 테스트 대상.
- 클립보드 복사: `navigator.clipboard` 사용, 실패 시 프롬프트 텍스트 전체 선택(select)으로 폴백
- 비교 뷰: 원문/결과 두 패널을 CSS grid 좌우 배치, 좁은 화면(<800px)에서 상하 배치
- 히스토리: `localStorage` 키 `essay_helper_history`에 JSON 배열. 항목 = `{ id, date, title(원문 첫 줄 30자), original, result, options }`. 저장/목록 렌더/클릭 시 폼 복원/삭제.

### 3.4 `style.css` — 스타일

따뜻한 톤(크림·코랄 계열)의 단일 페이지 스타일. 프레임워크 없음.

## 4. 에러 처리·엣지 케이스

- 원문이 비어 있으면 [프롬프트 생성] 비활성 + 안내 문구
- 지침을 하나도 선택하지 않아도 생성 가능 — ROLE_PREAMBLE의 기본 첨삭 지시만 포함
- 플랫폼 미선택 시 `general` 가이드로 동작
- localStorage 쓰기 실패(용량 초과 등) 시 안내 메시지 표시, 오래된 기록 삭제 유도
- 클립보드 API 미지원/거부 시 텍스트 자동 선택 폴백
