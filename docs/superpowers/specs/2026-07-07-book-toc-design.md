# 책 목차 추천 도구 (book_toc) 설계

날짜: 2026-07-07
상태: 설계 승인됨

## 목적

책 주제를 입력하면 예스24에서 해당 주제의 베스트셀러를 검색·분석하여, 사용자가 쓸 책의 목차 초안을 근거와 함께 추천하는 CLI 도구.

- 용도: 사용자 본인이 집필할 책(전자책 포함)의 뼈대 잡기
- 대상: 한국어 국내도서
- 결과물: 추천 목차 1안 + 참고한 베스트셀러 목록 + 장별 참고 근거 (마크다운)

## 접근 방식

원샷 파이프라인 CLI. 주제 하나를 인자로 받아 검색 → 크롤링 → LLM 분석 → 저장을 한 번에 수행한다. 기존 도구(youtube_summarizer, apt_landing)와 동일한 패키지 구조·설정 방식을 따른다.

검토했으나 채택하지 않은 대안:
- 대화형 2단계(책 선별 후 생성): 통제력은 좋으나 실행이 번거로움. 판매량순 상위권은 대부분 참고 가치가 있어 초기 버전에는 과함.
- LLM 에이전트식 반복 탐색: 로컬 llama3.1로는 안정성이 떨어지고 복잡도 과다.
- 알라딘 오픈 API: 사용자가 웹 크롤링 방식을 선택함.

## 아키텍처

```
book_toc/
├── __init__.py
├── config.py        # config.toml의 [book_toc] 섹션 로드
├── models.py        # Book(제목, 저자, 소개, 목차, URL), TocResult 데이터클래스
├── yes24.py         # 예스24 검색(판매량순) + 상세 페이지 소개글·목차 파싱
├── analyzer.py      # Ollama로 수집된 목차 패턴 분석 + 새 목차 생성
└── cli.py           # python -m book_toc "주제" 진입점
```

### yes24.py
- requests + BeautifulSoup 사용.
- 주제 키워드로 검색, 판매량순 정렬, 국내도서만 필터.
- 각 상세 페이지에서 제목·저자·책 소개·목차 전문을 추출.
- 목차가 없는 책은 건너뛰고, 목차 있는 책 `book_count`권(기본 5)을 채울 때까지 최대 15권 시도.
- 요청 간 1초 대기(서버 부담 최소화).

### analyzer.py
- apt_landing의 ollama_client.py를 재사용(또는 동일 패턴으로 호출).
- 프롬프트에 수집된 책들의 소개·목차를 넣어 두 가지를 생성:
  1. 베스트셀러들의 공통 구성 패턴 요약
  2. 사용자 주제에 맞는 새 목차(부/장/절 구조) + 장별 참고 근거
- LLM 출력은 자유 형식 마크다운으로 받아 그대로 사용(JSON 강제 파싱 없음).

### config.toml `[book_toc]` 섹션
- `ollama_model` (기본 "llama3.1")
- `output_dir` (기본 "book_tocs")
- `book_count` (기본 5)

### 산출물
`{output_dir}/{주제}_{YYYYMMDD}.md`:
- 추천 목차 (부/장/절)
- 장별 참고 근거 (어떤 책의 어떤 패턴을 참고했는지)
- 참고 도서 목록 (제목/저자/상세 페이지 링크)

## 데이터 흐름

1. `python -m book_toc "재테크 입문"` 실행
2. 예스24 검색 (판매량순, 국내도서)
3. 상위 결과 순회하며 상세 페이지 크롤링 → 목차 있는 책 5권 확보
4. Ollama로 패턴 분석 + 목차 생성
5. 마크다운 저장, 콘솔에 파일 경로와 미리보기 출력

## 에러 처리

| 상황 | 처리 |
| --- | --- |
| 검색 결과 0건 | "검색 결과가 없습니다. 더 일반적인 키워드를 시도해보세요" 안내 후 종료 |
| 목차 있는 책 2~4권 | 있는 만큼 진행, 결과물에 "N권 기준" 명시 |
| 목차 있는 책 2권 미만 | 중단, 사유 안내 |
| 개별 책 네트워크/파싱 실패 | 해당 책 건너뛰고 다음 책 진행 |
| 검색 요청 자체 실패 | 명확한 오류 메시지로 종료 |
| 예스24 HTML 구조 변경(파싱 결과 공백) | "사이트 구조가 변경된 것 같습니다" 안내 (조용한 실패 금지) |
| Ollama 미기동/오류 | 기존 도구와 동일한 연결 확인 안내 |

## 테스트 전략

pytest, 기존 `tests/` 패턴 준수. 네트워크 없이 실행 가능해야 한다.

- **yes24 파서**: 실제 검색 결과·상세 페이지 HTML을 픽스처로 저장하고 제목·저자·소개·목차 추출 검증. 목차 없는 페이지, 빈 검색 결과 케이스 포함.
- **analyzer**: Ollama 호출 모킹. 수집 데이터가 프롬프트에 올바르게 포함되는지, 응답이 결과 마크다운에 반영되는지 검증.
- **파이프라인**: 검색~저장 전 과정을 모킹으로 연결해 에러 경로(책 부족, 검색 0건 등) 검증.
- **수동 스모크**: 구현 후 실제 주제 1~2개로 엔드투엔드 실행해 크롤링·생성 품질 확인.

## 범위 제외 (YAGNI)

- 여러 서점 종합 수집
- 목차 후보 여러 안 생성
- 대화형 책 선별
- 웹 UI
