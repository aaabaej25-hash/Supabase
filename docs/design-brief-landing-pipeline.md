# 디자인 요청서 (Design Brief)
### 서비스명(가칭): PipeCraft — 랜딩페이지 제작 파이프라인 워크스페이스

> "랜딩-제작-프로세스" 12단계 파이프라인(디스커버리→카피→콘셉트→구조→와이어프레임→경험설계→비주얼시스템→에셋소싱→스펙&빌드→검증→CRO)을 단계별로 실행·승인·추적하는 웹앱의 프론트엔드 디자인을 Claude 디자인에 위임하기 위한 요청서입니다.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| **한 줄 설명** | 랜딩페이지 제작을 12단계 파이프라인으로 쪼개, 각 단계의 산출물을 작성·검토·승인(게이트)하며 처음부터 런칭 후 CRO까지 추적하는 워크스페이스 |
| **핵심 가치** | "감으로 만들지 말고, 검증 가능한 단계로 만든다" — 페이즈마다 산출물 1개 + 결재 게이트로 재작업을 막는다 |
| **타깃 유저** | 랜딩페이지를 다수 제작하는 에이전시·프리랜서 디자이너, 여러 프로젝트를 동시에 관리하는 PM/기획자 |
| **플랫폼** | 데스크톱 우선 반응형 웹 (실무 작업 도구 특성상 대형 화면 최적화, 태블릿 이상 대응) |
| **산출물** | 아래 8개 화면(+페이즈 작업 화면 템플릿 1종)의 하이파이 UI 디자인 + 화면 간 전환 흐름 |

## 2. 디자인 톤 & 무드 (제안)

- **분위기:** **차분한 프로페셔널 & 구조적** — 실무 도구(Linear·Notion·Height 계열)의 절제된 톤. 화려함보다 "지금 어느 단계에 있고, 무엇이 막혀 있는지"가 즉시 읽히는 명료함 우선
- **포인트 컬러:** **인디고/바이올렛 계열** (예: `#6366F1`~`#8B5CF6`)
  - 크리에이티브 작업 도구라는 인상은 주되, 랜딩페이지 자체의 색(고객사마다 다름)과 절대 혼동되지 않도록 툴 UI 색과 결과물 색을 명확히 분리
  - 게이트 승인 완료 = 그린, 대기 = 뉴트럴 그레이, 블로킹/반려 = 앰버·레드로 상태 색상 별도 체계 사용
- **베이스:** 뉴트럴(화이트/오프화이트 라이트, 딥 차콜 다크), 포인트는 인디고 1색으로 절제
- **타이포:** 가독성 높은 산세리프(Inter / Pretendard), 데이터·상태 라벨은 작고 명확하게, 헤드라인은 절제된 굵기
- **그래픽:** 플랫 + 미세한 그림자(카드/모달 구분용), 라운드 코너, 진행 상태를 보여주는 얇은 프로그레스 바·스테퍼 강조
- **다크모드:** 지원 (특히 파이프라인 진행 현황·페이즈 작업 화면 — 장시간 작업 도구 특성)
- **무드 키워드:** `명료한`, `신뢰감 있는`, `구조적인`, `절제된`, `실무형`

## 3. 유저 플로우 (전체 흐름)

```
[1. 온보딩/로그인]
      │
      ▼
[2. 프로젝트 대시보드] ──"새 프로젝트"──▶ [2-1. 프로젝트 생성]
      │ 프로젝트 카드 클릭                         │
      ▼                                          ▼
[3. 파이프라인 진행 현황] ◀──────────────────────────┘
      │ 페이즈 카드 클릭 (예: "P1 카피라이팅")
      ▼
[4. 페이즈 작업 화면] (P0~P9 공통 템플릿, 페이즈별 콘텐츠만 다름)
      │ 산출물 작성 완료 → "게이트 제출"
      ▼
[5. 게이트 승인 화면] ──(승인)──▶ [3. 파이프라인 진행 현황] (다음 페이즈 잠금 해제)
      │ (반려)
      ▼
[4. 페이즈 작업 화면] (수정 후 재제출)

전 페이즈 완료 시:
[3. 파이프라인 진행 현황] ──▶ [6. 산출물 미리보기] (빌드된 랜딩페이지 프리뷰)
```

## 4. 화면별 상세 요구사항

### 화면 1 — 온보딩 / 로그인
- **목적:** 최소 마찰로 진입, 도구의 성격(단계형 파이프라인)을 짧게 각인
- **필수 요소:**
  - 중앙 정렬 카드형 로그인 (Google 소셜 로그인 최상단·최강조)
  - 배경 또는 사이드에 파이프라인 12단계를 축약한 비주얼(스테퍼 그래픽)로 제품 성격 암시
  - 이메일/비밀번호는 보조 영역
- **상태 디자인:** 입력 에러, 로딩 버튼 상태 포함

### 화면 2 — 프로젝트 대시보드
- **목적:** 진행 중인 모든 랜딩 프로젝트를 한눈에 파악, 새 프로젝트 시작
- **필수 요소:**
  - 좌측 사이드바 (로고, 계정, 메뉴)
  - 프로젝트 카드 그리드: 프로젝트명 / 현재 페이즈 / 전체 진행률(0~9단계 중 몇 단계) / 마지막 업데이트일 / 블로킹 여부 뱃지
  - 검색 + 상태별 필터(진행중/게이트 대기/블로킹/완료)
  - **"새 프로젝트" 버튼** (우상단 primary 버튼)
  - **빈 상태(Empty State):** 프로젝트가 없을 때 "새 프로젝트로 첫 랜딩 파이프라인을 시작하세요" 안내
- **카드 인터랙션:** hover 시 빠른 액션(열기/복제/보관)

### 화면 2-1 — 프로젝트 생성
- **목적:** 신규 프로젝트의 기본 정보와 모드(Full/Lean) 설정
- **필수 요소:**
  - 프로젝트명 입력
  - **파이프라인 모드 선택:** Full 모드(전체 12단계) vs **Lean 모드**(포지셔닝→카피→와이어 1장→템플릿 빌드→전환측정 1개→런칭+A/B 1회의 최소 부분집합) — 라디오/토글로 명확히 구분, 각 모드가 포함하는 단계 수를 시각적으로 미리 보여줌
  - 참조 프로젝트(있다면) 연결 옵션
  - "파이프라인 시작" CTA

### 화면 3 — 파이프라인 진행 현황 (핵심 화면)
- **목적:** 프로젝트의 전체 12단계 지도와 각 단계의 상태를 한눈에, 다음 할 일을 명확히
- **필수 요소:**
  - **수평 또는 수직 스테퍼**로 P0~P9 전 단계 표시 (연속 트랙인 접근성·성능은 별도 배지로 상시 표시, 페이즈 칸에 끼워 넣지 않음)
  - 각 페이즈 노드 상태 4종을 색으로 구분: **잠김(미도달) / 진행중 / 게이트 대기 / 승인완료**
  - 의존 사슬(디스커버리→콘텐츠→콘셉트→구조→와이어→경험→톤→에셋→스펙→빌드→검증→런칭후) 표시 — 이전 단계 미승인 시 다음 단계 잠김 상태 명확히
  - 현재 페이즈 카드는 강조(테두리/색) + "이어서 작업하기" CTA
  - 완료된 페이즈 클릭 시 산출물 재열람 가능
- **무드:** 진행 상황을 한눈에, "막힌 곳"이 즉시 눈에 띄도록

### 화면 4 — 페이즈 작업 화면 (P0~P9 공통 템플릿)
- **목적:** 각 페이즈의 산출물을 작성·편집하고 게이트 제출까지 이어지는 작업 공간. 페이즈마다 입력 필드 구성은 다르지만 레이아웃 골격은 동일한 템플릿 1종으로 커버
- **필수 요소:**
  - 상단: 현재 페이즈명 + 전체 파이프라인 내 위치(예: "P1 카피라이팅 · 3/10단계") + 이전/다음 페이즈 이동
  - 좌측: 해당 페이즈의 참조 근거/체크리스트 패널 (예: P1이면 "보이스헌장·SMP·인지단계" 서브스텝 체크리스트)
  - 중앙: 산출물 편집 영역 (구조화 입력 폼 또는 리치 텍스트 에디터 — 페이즈별 산출물 스키마에 맞춰 폼 필드 동적 구성)
  - 우측 또는 하단: 이전 페이즈 산출물 참조 패널(의존 사슬 확인용, 예: 카피 작업 중 디스커버리 브리프 스니펫 표시)
  - 하단 고정 액션바: "임시저장" / **"게이트 제출"** (primary)
- **상태:** 초안 저장됨 / 제출됨(읽기전용) / 반려됨(수정 가능, 반려 사유 노출)

### 화면 5 — 게이트 승인 화면
- **목적:** 제출된 페이즈 산출물을 검토하고 승인/반려를 결정
- **필수 요소:**
  - 제출된 산출물 전체를 읽기 좋게 렌더링 (페이즈 작업 화면과 동일 데이터, 읽기 전용 뷰)
  - 승인 체크리스트(해당 페이즈의 게이트 기준 항목별 체크)
  - "승인" (primary, 그린 계열 상태색) / "반려" (사유 입력 필드 필수 동반)
  - 반려 시 반려 사유가 화면 4로 그대로 전달되는 흐름 명시
- **무드:** 결정의 무게감이 느껴지되 신속히 처리 가능하도록 간결하게

### 화면 6 — 산출물 미리보기
- **목적:** 전 페이즈 완료 후 실제 빌드된 랜딩페이지를 확인
- **필수 요소:**
  - 반응형 프리뷰 (데스크톱/태블릿/모바일 뷰포트 전환 토글)
  - 접근성·성능(CWV) 점수 요약 배지
  - "실배포" 전 최종 QA 체크리스트 사이드 패널
  - 원본 파이프라인으로 돌아가기

## 5. 공통 / 글로벌 요구사항

- **반응형:** 데스크톱 우선, 태블릿 대응 (모바일은 열람 전용 수준으로 축소 가능)
- **상태 디자인:** 잠김/진행중/게이트대기/승인완료/반려 5개 상태색 체계를 전 화면에 일관 적용
- **디자인 시스템:** 컬러 팔레트, 타이포 스케일, 버튼·인풋·카드·모달·스테퍼·상태 뱃지 컴포넌트 정의
- **접근성:** 명도 대비, 포커스 상태, 키보드 내비게이션 고려
- **일관성:** 8개 화면 + 페이즈 템플릿이 하나의 도구로 보이도록 통일된 컴포넌트/스페이싱

## 6. 산출물 & 우선순위

1. (필수) 화면 1~5 하이파이 디자인 + 페이즈 작업 화면 공통 템플릿 1종
2. (필수) 화면 간 전환 흐름 및 게이트 승인/반려 분기 흐름
3. (필수) 라이트/다크 모드
4. (권장) 화면 6(산출물 미리보기) + 핵심 컴포넌트 정리
